# Reglas de diseño de SEOCHECK

SEOCHECK es una herramienta profesional de análisis. La IA es una capacidad interna, no su identidad visual.

- Mostrar primero qué ocurre y qué hacer; después, evidencia y datos técnicos.
- Priorizar tablas, listas compactas, gráficos, jerarquía tipográfica y bordes discretos. Aprovechar el ancho disponible sin abreviaturas innecesarias.
- Evitar gradientes decorativos, glow, emojis, estrellas, mensajes promocionales, tarjetas repetidas y espacios vacíos excesivos.
- Mantener la información profesional mediante detalles expandibles, tooltips y opciones avanzadas. Simplificar no significa eliminar funcionalidades.
- Explicar métricas en contexto: qué miden, por qué importan y cómo interpretarlas. Mostrar unidades y una descripción del problema; el color nunca es la única señal.
- Usar Error / Advertencia / Observación, prioridad Alta / Media / Baja y estados Detectado / En progreso / Solucionado / Ignorado / Reapareció.
- Una incidencia por URL no es una tarea. Agrupar por problema y patrón; conservar evidencia e historial individual y describir las causas inferidas como hipótesis.
- Salud técnica es una métrica interna calculada. Las observaciones no descuentan puntos; no presentarla como score SEO general.
- El resumen muestra entre tres y cinco acciones relevantes; ocultarlo cuando no hay pendientes. Mantener widgets y gráficos de datos reales.
- Informe ejecutivo breve, descarga PDF principal. Markdown para implementación disponible al copiar, descargar o abrir la vista previa.
- Evitar párrafos permanentes. Usar una frase y detalles bajo Más información cuando corresponda.
- Mantener Keywords, Explorar, Rankings y Contenido como herramientas estructuradas. Conservar el grafo y sus acciones.
- Separar datos observados y recomendaciones. Etiquetar discretamente contenido generado: Generado con IA. No usar IA cuando basta una regla determinista.
- Conservar filtros, límites, configuración técnica e instrucciones de implementación para asistentes de programación mediante divulgación progresiva.

Validar escritorio, móvil, teclado, estados sin datos y conjuntos grandes. El estado vacío debe indicar qué falta y cómo obtenerlo.
